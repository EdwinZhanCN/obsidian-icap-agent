你的笔记是你学习的唯一记录。如果你卸载插件，笔记仍然完整、可读。如果插件丢失了自己的数据，你保留过的东西一样也不会丢。

## 保留的内容是普通的 Markdown

你保留一个结果时，插件把普通的 Obsidian Markdown 写进笔记：

| 你保留 | 笔记中写入 |
|---|---|
| 一条解释 | 一个 `gloss` callout |
| 一次回忆或检查 | 你的文字和一个 `feedback` callout |
| 一次测验 | 一个 `practice` callout |
| 一个请求块 | 一个 `request` callout，含你的请求、回复和文件链接 |

每条保留的记录上方还有一行注释，例如 `<!-- icap recall id=q7f3a2 date=2026-11-06 verdict=holds topic="RAII" -->`。阅读视图中，Obsidian 不显示这行注释。注释把日期和结果告诉其他工具。callout 的标题把同样的日期和结果告诉你。

插件读这些记录时，不需要自己的数据。其他工具也能读它们。插件源代码中的 `FORMAT.md` 文件说明了每种记录，记录的格式一改，格式版本号就改。

## 临时的东西不进文件

有些东西只在你工作时存在：

- 你没有保留的解释显示在编辑器中，但不在文件中。如果你选择 **丢弃**，文件不变，因为这条解释从来不在文件中。
- 进行中的问题块在文件中只是一个很短的 ```` ```icap-ask ```` 代码块。在你保留之前，回答和反馈都在插件的数据中。
- 你折叠一个块时，只有显示改变，文件不变。

所以，笔记中不会出现只有插件才能读懂的半段对话。如果你在没有插件的情况下打开笔记，进行中的块显示成一个很短的代码块。

## 对话就是块中显示的内容

一个请求块可以有很多轮。Agent 只知道块中显示的内容：你的请求和它的回复，按先后顺序。每开始新的一轮，插件都从块中生成这段文字。

在电脑上，插件还为这个块保存 Agent 的 Pi 会话，让下一轮开始得更快。这个会话只是缓存。只有它和块完全一致，插件才再次使用它。如果你改了块，或者会话不在了，插件把块中显示的对话交给一个新会话。在手机上，插件每次都这样做。

`/model`、`/thinking`、`/compact` 这样的命令改变 Agent 的工作方式。它们不进入对话，也不进入保留的记录。

## 保留是一个决定

在你保留之前，Agent 的输出都是临时的。选择什么留在笔记中，本身就是学习的一部分：你决定什么值得写进笔记。因此，插件不会自动保存所有内容。
