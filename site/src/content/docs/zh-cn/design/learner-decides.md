没有你的同意，Agent 不改你已有的笔记。你的回答始终是你自己的话。你能看到哪个任务改了哪个文件。笔记属于你，所以插件让你掌控笔记。

## 插件写什么

插件只写这些东西：

- 它自己的块，写进你开始任务的那篇笔记。
- 只在你打开 **把任务记录成笔记** 时：每个任务一篇任务笔记，放在 `ICAP/Tasks/` 中，以及 `ICAP/Activity.base` 文件，只写一次。

这一项默认关闭。很多库有自己的文件夹和规则，所以插件不添加你没要求的文件。插件把缓存放在它自己的文件夹里，不放在库中。

只有任务的状态改变时，插件才写任务笔记。它只设置自己的 `icap-*` 属性。任务笔记创建以后，插件不改它的正文。如果你删除一篇任务笔记，它就一直不在。要重新写出它，运行 **从最近的活动重建任务笔记**。

插件创建 `Activity.base` 以后，这个文件就属于你。插件不再写它。只有一个例外：早期版本生成的 base 会得到活动视图一次，作为它的第一个视图。

## 对已有笔记的修改只是建议

要修改一篇已有的笔记，Agent 提出一个修改建议。块把修改显示成差异对比：改动的行，以及上下各两行。然后你选择：

- **应用修改**：插件把修改写进笔记。
- **保持笔记原样**：笔记不变。

有些建议在你看到之前，插件就拒绝了。建议不能往笔记中加入 ```` ```icap-ui ```` 可视化。建议不能改动 ICAP 的块。Agent 可以改为把可视化放在回复中。

Agent 新建笔记不需要建议，因为新笔记不改动你写过的任何东西。活动列出每篇新笔记。插件还在新笔记的属性中写入 `generated-by: icap-agent`。要停止写入，关闭 **设置 → ICAP Learning Agent → 文件 → 标记 Agent 新建的笔记**。

## 你的回答始终是你自己的

在回忆、检查或测验中，Agent 把反馈写在你的回答下面。它不改你的回答。如果反馈指出了漏洞，你修改自己的文字。你保留结果时，插件写入的是你的话，不是 Agent 的话。

这条规则保护两种学习的区别。自己写出解释，是建构的学习。读 Agent 给的解释，是被动的学习。如果 Agent 改写了你的回答，你就分不清这两种了。

## 每处文件改动都有它的任务

对每个任务，插件记下 Agent 新建、修改、删除或重命名的文件。每篇任务笔记列出它的任务新建或修改的文件。活动显示同样的列表。

在电脑上，默认的 Agent 配置是 **你的 Pi 配置 + ICAP**。这时你自己的 Pi 工具可以直接改文件，例如通过 shell。插件不阻止这些改动。它把每处改动记在当时正在调用工具的任务上，或者记在不到三秒前刚结束的任务上。插件不记录这些文件：

- 任务自己所在的笔记，
- 任务笔记和 `Activity.base`，
- 你正在输入的笔记。

要更多的控制，把 **设置 → ICAP Learning Agent → 高级 → Agent 配置** 设为 **仅 ICAP（隔离）**。这时 Agent 只有 ICAP 的工具和 Pi 的只读工具。它只能新建笔记或提出修改建议。在手机上，Agent 总是这样工作。
