**设置 → ICAP Learning Agent** 中有两组设置和文件有关：**文件** 和 **资料**。

## 文件

| 设置 | 作用 | 默认值 | 平台 |
|---|---|---|---|
| **新笔记的位置** | Agent 新建笔记的文件夹。 | 空：由 Agent 决定 | 两者 |
| **标记 Agent 新建的笔记** | 在新笔记的属性中写入 `generated-by: icap-agent`。 | 打开 | 两者 |
| **把任务记录成笔记** | 为每个任务写一篇笔记，并创建 `Activity.base`。 | 关闭 | 两者 |
| **ICAP 文件夹** | 存放 `Activity.base` 和任务笔记的文件夹。只在 **把任务记录成笔记** 打开时显示。 | `ICAP` | 两者 |

### 新笔记的位置

如果这一项为空，Agent 为每篇新笔记选择文件夹。如果库中的 `AGENTS.md` 有规则，它按规则放。如果没有，它把笔记放在相关笔记所在的文件夹。如果没有合适的文件夹，它把笔记放在当前笔记所在的文件夹。

要把所有新笔记放在同一个文件夹，输入库中的一个文件夹路径，例如 `Learning/Concepts`。

在请求中，你随时可以告诉 Agent 把笔记放在哪里。你的请求优先于这一项。

### 标记 Agent 新建的笔记

打开这一项后，Agent 新建的笔记有属性 `generated-by: icap-agent`。Agent 用这个属性区分它自己的笔记和你的笔记。你写的笔记能说明你理解了什么，Agent 写的笔记不能。

除非你不想在笔记中看到这个属性，否则请保持打开。

### 把任务记录成笔记

关闭这一项时，插件不往你的库里写任何关于任务的内容。活动显示在插件自己的列表中。选择状态栏中的标记来查看。

打开这一项后，插件为每个真正干了活的任务写一篇笔记，并创建 `Activity.base`。之后你可以在 Bases 中筛选和排序任务。打开这一项时，插件也会为最近的任务写笔记。请看[任务笔记](/zh-cn/reference/task-notes/)。

如果你的库里有早期版本创建的 `Activity.base`，这一项是打开的。

### ICAP 文件夹

这个文件夹存放 `Activity.base`。任务笔记放在其中的 `Tasks` 文件夹，例如 `ICAP/Tasks/`。如果清空这一项，插件使用 `ICAP`。

插件只创建一次 `Activity.base`，之后不再改动它。ICAP 用 `icap-id` 属性找到任务笔记，所以你可以移动任务笔记。请看[活动](/zh-cn/learn/activity/)。

## 资料

Agent 可以读库中的 PDF、EPUB 和 Word（DOCX）文件。它像人一样读资料：先读目录，再读需要的章节。

| 设置 | 作用 | 默认值 | 平台 |
|---|---|---|---|
| **提前准备资料** | 在后台为库中的资料建立索引。 | 打开 | 两者 |
| **章节摘要** | 由模型为资料的每个部分写一句摘要。 | 关闭 | 两者 |

### 提前准备资料

打开这一项后，插件在任务需要之前先读每份资料。它找出章节和标题，把结果存在插件自己的文件夹 `.obsidian/plugins/icap-agent/docs/` 中。你的库里不会多出文件夹。这一步不用模型，所以不花钱。

插件随时可以重新生成这份缓存。如果一台设备上没有缓存，这台设备会自己准备资料。

如果关闭这一项，插件在任务第一次需要某份资料时才读它。

:::note
插件不能读没有文字层的扫描版 PDF。
:::

### 章节摘要

打开这一项后，模型为资料的每个部分写一次摘要。之后 Agent 在目录中能看到这些摘要。

:::caution
摘要要花 token。输入的 token 数约等于资料的字数。
:::

## 库外的文件夹

在电脑上，Agent 还可以读库外文件夹中的资料。这一项在 **高级** 一组中，只在 **Agent 配置** 为 **仅 ICAP（隔离）** 时显示。请看[Agent 配置](/zh-cn/settings/agent/)。
