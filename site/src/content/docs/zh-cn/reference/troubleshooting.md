## 提示和处理方法

| 提示 | 原因 | 处理方法 |
|---|---|---|
| “无法加载：Obsidian 的安装程序太旧，无法运行 Pi…”（在设置中，电脑上） | 你的 Obsidian 安装程序带的是 Node 20。Pi 需要 Node 22。Obsidian 在应用内的更新不会更换安装程序。 | 从 obsidian.md/download 下载最新的安装程序，覆盖安装当前的 Obsidian。库和设置都会保留。 |
| “还没有模型配置了凭证：请登录一个服务商。”（在设置中） | Pi 没有任何服务商的凭证。 | 在 **模型服务商** 中登录。如果 Key 在 shell 配置文件中，重启 Obsidian，然后选择 ↻（**重新检查**）。 |
| “还没有可用的模型：在下方添加 API Key。”（在设置中，手机或平板上） | 这台设备上没有 API Key。 | 在 **API Key** 中添加 Key。 |
| “这台设备上还没有设置模型服务商。请在设置中添加 API Key。” | 同上，在任务开始时出现。 | 在提示中选择 **打开设置**，添加 Key。 |
| “这台设备上没有 *服务商* 的 API Key。请在设置中添加。” | 任务的模型需要一个这台设备上没有的 Key。 | 在这台设备上添加 Key。Key 不同步。 |
| ““*模型*”在手机上不可用。请在设置中选择模型。” | 这个模型不属于手机上的服务商，也不属于你的端点。 | 在 **模型** 中选择其他模型。 |
| “没有“*模型*”这个模型。请在设置中选择一个。” | 这个服务商或端点没有这个模型名。 | 在 **模型** 中选择一个模型。 |
| “模型服务商拒绝了请求——请检查凭证（设置中的“模型服务商”）。” | 服务商回复 Key 或登录无效（401 或 403）。 | 重新登录，或重新输入 Key。确认你在服务商的账号可用。 |
| “连接模型时出现网络问题。” | ICAP 连接不上服务商。 | 检查网络连接和代理。然后在块中选择 **重试**。 |
| “模型服务商出错，正在重试…” | 服务商返回了错误，ICAP 正在重试。 | 等待。如果一直出现，查看服务商的状态页。 |
| “已暂停——连接中断了” | 连接中断了，例如应用被切到了后台。 | 重新打开笔记，选择 **继续**。 |
| “Obsidian 关闭时已暂停” | 任务运行时 Obsidian 关闭了。 | 选择 **继续**。 |
| “无法继续” | 任务失败。块中显示原因。 | 排除原因，然后选择 **重试**。 |

:::tip
如果任务因 `500`、`internal_error` 之类的错误失败，或者任务等了很久没有回复，先查看你的服务商的状态页。问题常常在服务商，不在 ICAP。
:::

### 整段返回的回复

在手机或平板上，有些自定义端点不允许应用以流式接收回复。这时回复整段返回，块中显示“等待完整回复…”。停止按钮是 **停止等待——这次请求仍会计费**。

:::caution
**停止等待** 只停止等待。服务器会完成这次请求，服务商照样计费。
:::

## 限制

### 在手机或平板上

- Agent 只用 ICAP 的工具。你的 Pi 配置（skills、扩展、MCP 服务器、`/compact`）不可用。没有文件工具和 shell 工具。
- 只能用 API Key 或自定义端点。订阅登录、Bedrock 和 Vertex 不可用。
- Agent 不能读取库外的文件夹。
- ICAP 不保存会话。请求块的每一轮都把整段对话重新发给模型。
- 手机或平板上的模型和电脑上的模型是两个不同的设置。

### 解释和块

- 选区标记只在实时预览和源码模式中显示。
- 没有保留的解释在插件重新加载时消失。块会保留，你可以继续。
- 任务在暂停后继续时，ICAP 把对话发到一个新的会话。Agent 的下一个问题可能和原来要问的不同。

### 交互式图示

- ICAP 不保存交互式图示的状态。
- 在阅读视图中，如果笔记中没有请求块，图示通过一个新的请求块提问。这要求笔记可以编辑。

### 资料

- ICAP 不能读取没有文字层的扫描 PDF。它没有文字识别（OCR）。

### 在电脑上

- 只有 Pi 自己的代码通过 Node 联网。如果你自己的某个 Pi 扩展直接联网，它在 Obsidian 中运行，服务器必须允许来自应用的请求（CORS）。在 Pi 命令行中，同一个扩展没有这个限制。
- 插件中没有 Pi 的 code mode。

### 大小

`main.js` 约 13 MB。它包含电脑用的 Pi，以及手机和平板用的模型库。手机或平板只加载它需要的库。
