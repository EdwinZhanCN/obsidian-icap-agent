任务笔记是 `ICAP/Tasks/` 中记录一个任务的笔记。Obsidian 的 Bases 和其他工具，可以按这些笔记的属性列出任务。这个列表就是活动，在 `ICAP/Activity.base` 中。

只有打开 **把任务记录成笔记**（**设置 → 文件**）时，ICAP 才写任务笔记。这一项默认关闭。打开时，ICAP 为最近的任务写笔记，并创建 `Activity.base`。

## ICAP 什么时候写任务笔记

| 任务 | 任务笔记 |
|---|---|
| 写笔记的任务（**用选中内容新建概念笔记**、**把本笔记的关键概念整理成笔记**、**写一篇对比笔记…**） | 总是写。 |
| 请求块 | 只在对话成为任务时写：Agent 用了工具，Agent 新建、修改或删除了文件，Agent 向你提了问题，或者这个块有多于一轮的对话。 |
| 只有一个问题和一个回答的请求块 | 从不写。 |
| 解释、回忆、检查或测验 | 从不写。 |

斜杠命令 `/model`、`/thinking` 和 `/compact` 不算轮次。一个请求块的所有轮次都更新同一篇任务笔记。

ICAP 按 `icap-id` 找任务笔记，不按路径。你可以给任务笔记改名，或把它移到其他文件夹。

## 任务笔记放在哪里

任务笔记放在 `ICAP/Tasks/`。要换一个文件夹，在设置中更改 **ICAP 文件夹**。这个文件夹存放 `Activity.base`，任务笔记放在其中的 `Tasks` 文件夹。

如果你删除了一篇任务笔记，ICAP 不会自己重新写它。要重新写，运行 **从最近的活动重建任务笔记**。这个命令只知道最近 60 个任务。

## 属性

| 属性 | 类型 | 意思 |
|---|---|---|
| `icap` | 文本 | 总是 `task`。工具按这个属性找任务笔记。 |
| `icap-id` | 文本 | 任务的 id。对请求块，是块的 id。 |
| `icap-status` | 文本 | 任务的状态。见下一个表。 |
| `icap-source` | 链接列表 | 任务涉及的笔记：请求块所在的笔记，或任务开始时所在的笔记。 |
| `icap-changed` | 链接列表 | 任务新建或修改的文件。 |
| `icap-started` | 日期和时间，本地 | 最近一次运行的开始时间。 |
| `icap-ended` | 日期和时间，本地 | 最近一次运行的结束时间。状态是 `running`、`needs-you` 或 `review` 时没有这个属性。 |
| `icap-cost` | 数字，或文本 `unknown` | 任务所有运行的花费，单位是美元。 |
| `icap-tokens` | 数字 | 所有运行输入和输出的 token 数，包括缓存的 token。 |
| `icap-cache` | 数字，0 到 100 | 服务商从缓存读取的提示词所占的百分比。 |
| `icap-model` | 文本，`provider/id` | 最近一次运行的模型。 |

属性没有值时，ICAP 不写这个属性。ICAP 只改这些属性，不改其他属性。新建任务笔记以后，ICAP 不改它的正文。

### 状态值

| `icap-status` | 意思 |
|---|---|
| `running` | Agent 正在处理这个任务。 |
| `needs-you` | Agent 向你提了问题，在等你回答。 |
| `review` | Agent 提议修改一篇笔记，你还没有应用或拒绝。 |
| `done` | 任务完成。 |
| `failed` | 任务因为错误而停止。 |
| `cancelled` | 你停止了任务，或者任务运行时 Obsidian 关闭了。你可以在它的块中继续。 |

`draft` 和 `queued` 是保留值，这个版本不写。

状态只表示任务处在什么阶段。任务此刻在做什么，例如在读哪个文件，不在笔记中。

### 花费

`icap-cost` 是按模型的标价估算的。如果服务商报告了实际计费，ICAP 用这个数。

:::note
`icap-cost` 从不用 `0` 表示“不知道”。ICAP 无法算出花费时，写 `unknown`。没有标价的模型（例如自定义端点）和 ICAP 开始记录花费之前的任务，都是这种情况。已结束的任务总是有 `icap-cost`。
:::

如果你用订阅登录，服务商不按 token 计费。这时的数字表示同样的用量按标价要花多少。

## Activity base

ICAP 只生成一次 `ICAP/Activity.base`。之后，这个文件归你，ICAP 不再写它。只有一个例外：早期版本生成的 base 会得到 **活动** 视图，作为第一个视图，只加一次。

这个 base 显示 `icap` 为 `task` 的所有笔记。它有这些视图：

| 视图 | 显示什么 |
|---|---|
| **活动** | ICAP 自己的视图（`icap-activity`），最新的在前。需要插件。 |
| **需要我** | 状态为 `needs-you` 或 `review` 的任务表格。 |
| **进行中** | 状态为 `queued` 或 `running` 的任务表格。 |
| **全部** | 所有任务的表格，按状态分组。花费和 token 有合计。 |

三个表格不需要插件。卸载插件后，Bases 提示 **活动** 的视图类型未知，表格仍然可用。

**全部** 表格有一列 **用时（分）**，从 `icap-started` 算到 `icap-ended`。花费的合计不包括 `unknown`。

### base 中的属性名

属性名中有连字符。Bases 在表达式中把连字符读作减号。所以属性名有两种写法：

| 位置 | 写法 |
|---|---|
| 筛选条件或公式中 | `note["icap-status"]` |
| 作为列、分组或显示名 | `note.icap-status` |

:::caution
在筛选条件或公式中，总是写 `note["icap-status"]`。Bases 把单独的 `icap-status` 读作 `icap` 减 `status`。
:::

查看活动，见[活动](/zh-cn/learn/activity/)。
