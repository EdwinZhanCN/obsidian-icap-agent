A request block is a place in the note where you write to the agent in your own words. The agent can read your notes and documents, write new notes, and propose changes to your notes. The block shows the reply and the files that the agent touched. You decide what stays in the note.

<RequestDemo client:only="svelte" lang="en" kind="request" />

## Open a request block

1. Put the cursor where you want the block. To give the agent a passage, select it.
2. Open the command palette and run **Ask the agent here**. You can also right-click in the note and select **Ask the agent here**.

The block opens below the paragraph that has the cursor. If you selected text, the agent gets the selection with the request. On a phone, the command is in the toolbar.

To close an empty block, select **not now**.

## Write the request

1. Write the request.
2. Select **send**, or press ⌘ Enter (Ctrl Enter on Windows and Linux).

While the agent works, the block shows what it does, for example *thinking…* or *writing…*. To stop the agent, select **stop**. To start it again, select **continue**. If the task failed, select **try again**.

The agent gets your words as you wrote them. It also gets the name of the note, the heading above the block, and the selection.

## Link a file

To tell the agent which notes or documents to use, link them in the request.

1. Type `[[` or `@`.
2. Type a part of the file name.
3. Select the file in the list.

The plugin writes an ordinary link, for example `[[Bernoulli's principle]]`. `@` is a shorter way to type the same link. The agent gets the path of each file, not its content. It reads what it needs with its own tools.

## Use a command

A request that starts with `/` is a command. Type `/` to see the list of commands.

| Command | What it does |
|---|---|
| `/model` | Uses a different model for this block only. `/model default` goes back to the model in the settings. Without a name, it shows the model of the block. |
| `/thinking` | Sets the thinking level for this block only: `off`, `minimal`, `low`, `medium`, `high` or `xhigh`. `/thinking default` goes back to the settings. |
| `/compact` | Summarizes the earlier rounds for the agent. The note does not change. Desktop only. |

These three commands answer with a short line in the block. They are not part of the conversation, and the record does not include them.

With **Your Pi setup + ICAP** (**Settings → ICAP Learning Agent → Advanced → Agent setup**), the list also shows your own Pi skills, prompt templates and extension commands. With **ICAP only (isolated)**, the list shows only the three commands above. Commands work only in a request block. In a recall, a check or a quiz, a `/` at the start is ordinary text.

## Review a proposed change

The agent does not change an existing note by itself. It proposes the change in the block:

- The title shows **Proposed change to** and the name of the note.
- The lines that the agent removes have a −. The lines that it adds have a +.

Then do one of these:

- To write the change into the note, select **apply change**.
- To keep the note as it is, select **leave the note as is**.

The agent then continues. After your decision, the change folds to one line, for example *accepted · +2 −0*. Select the line to see the change again.

:::note
With **Your Pi setup + ICAP**, the agent also has your own Pi tools. These tools can change files directly, without a review. The block and the [activity](/learn/activity/) list each file that the agent made, changed or deleted.
:::

## Ask a follow-up

When the agent is done, a line with **Follow up…** shows below the reply.

1. Write the follow-up. You can use `[[`, `@` and `/` here too.
2. Select **send**.

The conversation continues in the same block. Earlier rounds fold to one line each. Select a line to open it again.

What the agent knows of the conversation is what the block shows. On desktop, with **Remember a request's context** on (**Settings → ICAP Learning Agent → Advanced**), the agent continues its earlier session while that session agrees with the block. On a phone, each follow-up sends the whole conversation to the model again.

## See what it cost

Below the reply, a line shows the tokens, the part of the prompt that came from the cache, and the price of the conversation, for example *7.7k tokens · cache 42% · ≈$0.012*. ≈ marks an estimate from the list prices of the model. If the price is not known, the line shows *cost unknown*.

## Keep a record

When the agent is done, select **keep a record**. The plugin replaces the block with a `request` callout:

- each of your requests, after **Request:**
- the reply of the agent
- after **Files:**, a link to each file that the agent made or changed

The links in the record are ordinary links, so the graph shows which notes the request used.

To remove the block, and keep nothing, select **clear**. The files that the agent made or changed stay as they are.

If the request became a task (the agent used a tool, touched a file, asked you a question, or the conversation has more than one round), the plugin also records it in a task note. See [Activity](/learn/activity/).
